==================================================
1. ОБЩАЯ ИДЕЯ ПРОДУКТА
==================================================

Это современное мобильное приложение для поиска авиабилетов.

Пользователь должен иметь возможность:

- выбрать город/аэропорт отправления;
- выбрать город/аэропорт назначения;
- выбрать дату вылета;
- при необходимости выбрать обратную дату;
- указать количество пассажиров;
- найти доступные авиарейсы;
- сравнить варианты;
- использовать фильтры и сортировку;
- открыть подробную информацию о рейсе;
- увидеть цену, время, длительность, авиакомпанию, аэропорты, багаж и другие параметры;
- выбрать подходящий рейс;
- выбрать место;
- ввести данные пассажира;
- пройти mock checkout;
- подтвердить бронирование;
- получить электронный билет;
- видеть свои поездки.

Это НЕ просто интерфейс из нескольких форм.
Приложение должно выглядеть и ощущаться как настоящий polished consumer travel product.

==================================================
2. КЛЮЧЕВАЯ ИДЕЯ UX
==================================================

Приложение должно работать даже без авторизации.

Не нужно блокировать пользователя экраном Login сразу после Splash.

Первый сценарий:

Splash
→ Home / Explore

Без аккаунта пользователь может:

- искать рейсы;
- менять маршрут;
- выбирать даты;
- смотреть результаты;
- сортировать;
- фильтровать;
- открывать карточку рейса;
- сравнивать варианты.

Авторизация требуется только тогда, когда пользователь пытается:

- забронировать рейс;
- сохранить персональные данные;
- открыть персонализированные функции;
- просматривать свои бронирования.

Если незалогиненный пользователь нажимает «Забронировать»:

показать auth flow:

Войти
или
Создать аккаунт

После успешной авторизации пользователь должен вернуться к тому же выбранному рейсу и продолжить бронирование, а не быть отправлен на Home.

5. ВИЗУАЛЬНЫЙ СТИЛЬ
==================================================

НЕ делать стандартный безликий Material Design demo.

Нужен современный premium travel UI.

Основной фон:
не чистый #FFFFFF, а слегка теплый/холодный off-white.

Например примерно:

#F7F8FA
или близкий оттенок.

Основной accent color пока можно временно использовать premium blue, близкий по ощущению к Booking.com / современным travel fintech приложениям.

Например:
глубокий насыщенный blue, но не слишком кричащий.

Потом цветовая система будет заменена, поэтому цвета должны находиться централизованно в theme/design system.

Никаких hardcoded цветов по всему проекту.

Нужно создать централизованные:

- AppColors;
- typography;
- spacing;
- border radius;
- shadows;
- button styles;
- input styles;
- card styles.

Визуальное направление:

- premium;
- clean;
- современное;
- много воздуха, но не пустота;
- хорошая typography hierarchy;
- качественные cards;
- красивые bottom sheets;
- мягкие transitions;
- аккуратные micro-interactions;
- rounded corners;
- restrained shadows;
- никаких дешевых gradients ради gradients;
- никаких огромных пустых Material карточек.

Flutter должен использоваться свободно, а не ограничиваться стандартными Material widgets без кастомизации.

==================================================
8. СРАВНЕНИЕ И «ВЫГОДНЫЙ РЕЙС»
==================================================

Ключевая особенность приложения — помочь выбрать выгодный рейс, а не просто показать список билетов.

Нужно реализовать хотя бы базовую систему:

Cheapest
Fastest
Best

Например:

Cheapest:
самая низкая цена.

Fastest:
минимальное общее время полета.

Best:
условный score на основе:

- цены;
- времени;
- количества пересадок;
- багажа.

Не нужно делать настоящий AI.

Можно сделать понятный deterministic scoring algorithm.

Также можно отображать:

«Выгодная цена»
«Лучший вариант»
«Самый быстрый»

==================================================

Ниже требования преподавателя, переведенные на русский.

1. Тема, цель и задачи курсового проекта

Должны быть:

- определена тема приложения;

Должны быть:

- состояние авторизации пользователя должно обрабатываться.

6. Главная страница

- рабочие элементы интерфейса;

7. Основная навигация

- логичная структура навигации;

8. Профиль

- дизайн соответствует всему приложению.

9. Основной раздел приложения

Должна быть реализована первоначальная полноценная версия основного функционала.

В нашем случае это:

поиск авиабилетов
→ результаты
→ сравнение
→ выбор рейса
→ бронирование.

Пользователь должен реально иметь возможность пройти основной сценарий.

10. Logout

Должны быть:

- рабочая кнопка выхода;
- пользователь выходит из аккаунта;
- после logout открывается экран авторизации или guest state;
- защищенные пользовательские разделы требуют повторной авторизации.
